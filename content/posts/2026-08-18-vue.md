# Vue核心  
## Vue简介  
* vue是一套用于**构建用户界面**的**渐进式**JavaScript框架  
	- 渐进式：简单引用只需要引入一个轻量小巧的核心库；复杂应用：可以引入各式各样的Vue插件  
* Vue的特点：  
	1. 采用组件化模式，提高代码复用率，让代码更好维护  
		- 组件化：相当于网页上的一个小地方，存在html、css、JavaScript组合在一起的vue文件  
	2. 声明式编码，让编码人员无需直接操作DOM，提高开发效率  
		- 之前编码js操作网页采用是命令式编码  
	3. 使用虚拟DOM+优秀的Diff算法，尽量复用DOM节点  
		- 数据存在变换，虚拟DOM有很大的帮助  
		- Diff算法作用于虚拟DOM中，算法优化效率


	6. {{xxx}}中的xx需要写JS表达式，并且xxx可以自动读取到data中的所有属性  
	7. 一旦data中的数据发生改变，那么页面中用到该数据的地方也会自动更新  

## Vue模板语法  
* 插值语法  
	- {{xxx}},xxx中是js表达式，自动读取对于绑定的Vue对象中的data属性  
* 指令语法  
	- v-bind:指令，会让后面的**标签属性**中字符串的值作为js表达式去执行，自动读取对于绑定的Vue对象中的data属性  
		* ``<a v-bind:href="url"></a>``  
		* v-bind:可以简写成:  
	- 指令语法功能：用于解析标签（标签属性、标签体内容、绑定事件......）,指令存在多个，形式都是v-xxx...  
* 区分：  
	- 标签体中可以使用插值语法  
	- 标签属性可以使用指令语法  

## 数据绑定  
* 单项数据绑定：  v-bind是一个单向绑定，即只能data影响页面中的值，反向无法进行影响  
* 双向数据绑定：v-model是一个双向绑定，即双向影响  
	- 注意v-model只能用在表单元素上，即存在用户输入的情况（value）  
	- v-model:value可以简写为v-mode，因为默认就是收集的value属性  
## el和data的两种写法  
* Vue对象中的带$符号的属性都是给程序员使用的  
* 之前需要使用Vue对象中的属性el指定容器，除此之外，还可以使用其原型上的**$mount**方法，参数传入选择器也可以替代其指定容器（更加灵活）  
* data之前的写法是对象式，还存在一种写法：函数式，一个匿名函数，返回值必须要返回需要的对象（后续组件编写需要使用），**注意需要写普通函数，this才能指向Vue对象**  
	- 注意在一个属性中写匿名函数，可以直接属性名:function(){}替换为属性名(){}简写  

## MVVM模型  
1. M：模型Model：对应data中的数据  
	- data中的key-value值最终会成为vm实例对象中的属性（数据代理），从而被模板对应起来 
	- data中的数据一旦发生修改，模板都会据此进行重新解析一遍  
2. V：视图View：模板(DOM)  
	- 本质是可以看到vm中的所有属性的（包括原型上-继承或者方法嘛），所以都可以直接使用（通过js表达式的形式）  
3. VM：视图模型(ViewModel):Vue实例对象  
	- 以后接收实例对象的时候变量名命名为vm

## 数据代理  
### Object.defineproperty  
* Object.defineproperty(对象名, 属性名, {配置项} )  
	- 配置项value可以给属性名设置value值  
	- 注意此方法，对应属性值不能被枚举，可以通过配置项enumerable:true设置其可以被枚举  ，默认为false   
	- 属性值默认不可被修改，writable:true配置项可以设置其可以被修改  
	- 属性值默认不可被删除，configurable:true配置项可以设置其可以被删除  
	- ...  
	- 高级配置:   
		* get:function(){return  xx;}  -getter对属性读取进行设置回调函数   
		* set:function(value){xxx} -setter对属性进行设置时候会被调用，设置的同时会收到修改的具体值  
### 数据代理定义：  
* 实际上数据代理就是**通过一个对象代理对另一个对象中属性的操作（读/写）**   
	- 代理对象中通过设置getter和setter得到或者操作被代理对象的属性即可  
```js
        let a = {x: 1};
        let b = {y: 2};
        // 下面通过b对象对a对象的x属性进行一个代理，设置setter和getter即可
        Object.defineProperty(b, "x", {
            set:function(value){
                a.x = value;
            },
            get(){
                return a.x;
            }
        });
```

### Vue中的数据代理  
* vm中的``_data``就等于之前定义时程序员写的配置项中的data对象  
* 存在这样的一种场景，由于我们在模板上可以写任意vm中的属性对象-js表达式显示出来，但是我们在data中配置的属性，则体现在模板上就需要``_data.属性名``的方式体现出来，比较麻烦，所以在vm中，针对于data的所有属性，进行了一个数据代理，属性名照搬，设置setter和getter（为了编码方便）  
* 通过Object.defineProperty方法实现  
* 即通过vm的对象来代理data对象中属性的操作（读和写）  
* ``·vm._data``中不要认为是数据代理，是为了实现响应式的操作，实现的是数据劫持，数据劫持后续会讲  

## 事件处理  
### 事件的基本使用  
* 使用指定语法给对应元素绑定对应事件的回调函数  
	- ``<button v-on:click="函数名">按钮</button>``  
	- v-on:事件名="函数名"  
* 回调函数需要通过vm配置项**methods**内配置即可。（对象中直接写方法需要将function去掉）  
* 简写方式：@事件名="函数名(实参)"  
	- 注意这样会把默认传入的第一个实参event给搞丢（事件对象），可以在传参里输入$event可以占位一个事件对象参数  
	- 不写函数的(实参)=>函数名($event);  
* 注意函数对象是直接映射到Vue对象中，并没有做数据代理（固定写死了的）  
* methods中配置的函数，this指向vm或者组件实例对象  
* 需要注意在模板中双引号内的函数可以写一些简单的一行语句，引用Vm中的数据即可（注意只推荐1行能解决的函数这样写，出现多行使用;间隔也能写，但是并不推荐）  
	- 直接写语句注意的一点，使用的函数只会在vm中去查找，没有就会去报错  

### 事件修饰符  
* 对于一个事件触发，可能存在一些条件需要去阻止默认的行为，比如冒泡、默认事件、事件只触发一次等等... 这些在JS中需要通过事件对象的方法进行修改，在Vue中可以通过事件修饰符做到简单的修改  
* Vue中的事件修饰符：  
	1. prevent: 阻止默认事件(常用)  
	2. stop: 阻止事件冒泡(常用)  
	3. once:事件只触发一次（常用）  
	4. capture:使用事件的捕获方式  
	5. self：只有event.target是当前操作的元素才能触发事件  
	6. passive: 事件的默认行为为立即执行，无需等待事件回调函数执行完毕  
* @事件名.修饰符="函数"  
* 注意如果想要同时修饰多个事件，可以连续写修饰符：``@事件.修饰符1.修饰符2="函数"``,效果从左到右依次执行  

### 键盘事件  
* 在input输入框中，在之前的js代码中，我们向其输入数据，不能随时通过键盘绑定事件直接获取，可能会通过回车判断用户是否输入完毕然后在进行提取，可以通过event,key的13号编码进行逻辑判断即可，在Vue中存在对键盘事件的修饰代替这个判断逻辑的工作,比如enter，表示按下enter后执行回调函数  
* Vue中常用的按键别名：  
	1. 回车 - enter  
	2. 删除 - delete(捕获删除和退格（back）键)  
	3. 推出 - esc  
	4. 空格 - space  
	5. 换行 - tab  
		* tab键本身存在一个功能就是切换焦点，所以不适配keyup键盘事件，使用keydown即可  
	6. 上 - up  
	7. 下 - down  
	8. 左 - left  
	9. 右 - right  
* 对于没有提供别名的按键，可以通过按键的原始key值去绑定，但是需要注意转为kebab-case（短横线命名，即将小驼峰全部转换为小写，中间使用-进行间隔）  
* 系统修饰键（用法特殊）：ctrl、alt、shift、meta（win）  
	1. 配合keyup使用：按下修饰键的同时，再按下其他键，随后释放其他键，事件才会触发  
		* 注意可以在系统修饰键后面指定一个键配合这个键释放才能触发，而不是随便什么键  
	2. 配合keydown使用：正常触发事件  
* 也可以配合KeyCode的去绑定（但是不要去使用，已经移除web标准了）  
* 可以通过设置Vue的配置设置自定义键名：  
	- Vue.config.keyCodes.自定义键名 = 键码;可以定制键名  

## 计算属性  
* 例子引入：现在想实现一下输入一个人的姓和名，然后下方自动拼接姓名展示出来，并且可以跟着动态的进行变换  
- 插值写法  
```html
<body>
    <div class="root">
        姓: <input type="text" v-model="fristName"><br>
        名: <input type="text" v-model="lastName"><br>
        姓名: <span>{{fristName}}{{lastName}}</span>
    </div>
    <script>
        const vm = new Vue({
            el: ".root",
            data:{
                fristName: "柒",
                lastName: "海"
            }
        });
    </script>
</body>
```
- methods写法  
```html
<body>
    <div class="root">
        姓: <input type="text" v-model="fristName"><br>
        名: <input type="text" v-model="lastName"><br>
        姓名: <span>{{showName()}}</span>
    </div>
    <script>
        const vm = new Vue({
            el: ".root",
            data:{
                fristName: "柒",
                lastName: "海"
            },
            methods: {
                showName(){
                    return this.fristName+this.lastName;
                }
            }
        });
    </script>
</body>
```
* 就插值写法而言，如果我们对其中一个数据获取需要复杂的需求，那么模板里表达式就会越来复杂，这很明显不符合Vue的设计理念，所以Vue设计了计算属性，能完美的将模板里完成的表达式工作转接到了js代码上（这样不需要通过methods去间接的设计了）  

### 计算属性实现  
* Vue中认为vm中data内的数据为属性，所谓的计算属性，就是拿着已有的属性去计算为一个全新的属性  
* Vue中计算属性是一个全新的配置项，写在：**computed**中，value还是为对象  
* 在计算属性中，由于写成了计算属性，那么会认为很复杂，则同数据代理设计的那样，对计算属性（computed）中的某个属性，需要设置getter和setter回调函数（配置对象的方式）  
* 并不是对计算属性读一次就调用一次get函数，**Vue中做了一个缓存**（优势）。  
	- get什么时候调用？1.初次读取计算属性时，2.所依赖的数据发生变换的时候  
```html
<body>
    <div class="root">
        姓: <input type="text" v-model="fristName"><br>
        名: <input type="text" v-model="lastName"><br>
        姓名: <span>{{Name}}</span>
    </div>
    <script>
        const vm = new Vue({
            el: ".root",
            data:{
                fristName: "柒",
                lastName: "海"
            },
            computed:{
                Name:{
                    get(){
                        return this.fristName + this.lastName;
                    }
                }
            }
        });
    </script>
</body>
```

### 计算属性简写  
* 更多情况，计算属性只是计算现有的属性展示在页面上，所以不会怎么使用setter函数  
* 在只读不改的情况下，可以不用写成配置对象的形式，计算属性名:function(){}，这种function也可以省略掉  

## 监视属性  
### 基本使用  
* 顾名思义，监视一个属性的变化  
* 在Vue中，存在配置项watch指定监视属性，value为配置对象  
* 使用watch：  
	1. 想监视哪个属性，就直接写属性名，后面跟上配置对象  
		- 属性包括计算属性  
	2. 配置中写handler为其配置回调函数，会在对应属性发生变化时就会调用此函数  
		- handler函数存在两个参数：newValue、oldValue表示修改的这次修改前和修改后的值  
	3. 配置中写immediate，其是bool值，默认为false，如果设置true，会让回调函数立即执行（初始化时）  
* 除了使用watch进行监视，可以使用vm.$watch(属性名, 配置对象);同样可以实现监视  
### 深度监视  
* 现在我们想检测多级结构中某个属性的变化  
* 当我们想检测属性中的属性（对象中的属性）的时候，不可直接写其属性名，需要属性名.属性名的方式去写。但是注意这样写需要加''表示属性  
* 但是注意，如果我们想要检测某个属性中的全部属性如果发生变化，直接监视这个属性名是不起效果的  
* 在watch配置中开启配置deep为true即可（默认为false），此时便就可以深度监视内部属性的变化了  

### 监视的简写  
* 简写形式的前提：只存在handler配置项，不存在其他的配置项即可（不需要深度检测和初始化调用一次）  
* 属性名:function(newValue, oldValue){} 当然也能写成：函数名(newValue, oldValue){}  
* 同样的，在vm.$watch('属性名', function(){});即可简写，此时此回调函数就是给handler配置的  
* 下面是使用监视属性写计算姓名，并且同步姓名的例子：  
```html
<body>
    <div class="root">
        姓: <input type="text" v-model="fristName"><br>
        名: <input type="text" v-model="lastName"><br>
        姓名: <span>{{name}}</span>
    </div>
    <script>
        const vm = new Vue({
            el: ".root",
            data:{
                fristName: "柒",
                lastName: "海",
                name: "柒 海"
            },
            // 监视属性，属性发生改变时调用
            watch:{
                fristName:{
                    handler(newValue){
                        this.name = newValue + ' ' + this.lastName;
                    }
                },
                // 只有handler配置项的时候的简写形式
                lastName(newValue){
                    // 使用监视的优势，异步操作
                    setTimeout(()=>{
                        this.name =  this.fristName + ' ' + newValue;
                    }, 1000);  // 注意这个回调函数需要写箭头函数才能让里面的this指向的是vm  
                }
            }
        });
    </script>
</body>
```

### 监视和计算属性之间的区别：  
1. computed能完成的功能，watch都可以完成  
2. watch能完成的功能，computed不一定完成，例如：watch可以进行异步操作  
* 原则：  
	1. 所有被Vue管理的函数，最好写成普通函数，这样this的指向才是vm或组件实例对象  
	2. 所有不被Vue所管理的函数（定时器的回调函数，ajax的回调函数等），最耗写成箭头函数，这样this的指向才是vm或 组件实例对象。（箭头函数的this是根据其所处的外层作用域决定的）  

## 绑定样式  
* 绑定class样式-字符串写法，适用于类名不确定，需要动态指定  
* 绑定class样式-数组写法，适用于要绑定的样式个数不确定、名字也不确定  
* 绑定class样式-对象写法，适用于样式个数确定，名字也确定，但是要动态决定用不用  

* 上述均是使用v-bind绑定模型中标签的属性，vm中的data配合methods进行样式的调整  
* 除开class绑定样式，还能设置内联样式：v-bind:style="js表达式" ,在js表达式中写成对象即可  
	- 需要注意样式的对象写法，key均要以小驼峰进行命名（原始css中的样式带有-的需要进行注意）  
	- 除了对象写法，还存在数组写法，数组里的元素为对象（样式对象，相当于发生了嵌套）  

## 条件渲染  
* 模板上存在一个指令**v-show**，可以指定js表达式，表达式为真显示此标签，否则不会显示（类似于之前的隐藏元素）  
	- 底层实现就是display属性  
* 使用**v-if**同样可以作为条件渲染，类似的，只不过如果不显示的话会在html结构上将其删除  
	- 存在if了也会存在elseif、else，使用**v-else-if**在模板上承接着v-if，实现类似的效果（需要一组）。这样效率就能高一点（每次渲染模板的时候就会跳过对应的渲染标签）。也存在v-else指令，并且不需要写条件了（也能没有作用）  
* 另外，如果存在一组有相同条件的标签，但是不想重复写（在不破坏原本结构的条件下），可以使用template标签，用v-if（不可使用v-show）条件对其进行设置可以实现这样的效果  
* 总结：  
> v-if="表达式"，可以写else、else-if。适合切换频率低的场景，特点：不展示的DOM元素直接移除  注意其一起使用的适合结构不能被打断  
> v-show="表达式"，适用于切换频率高的场景，特点：不展示的DOM元素没有被移除，仅仅使用css样式属性隐藏掉  
> 备注：使用v-if元素可能会获取不到（DOM树结构删除）、v-show一定获取的到  

## 列表渲染  
### 基本列表  
* 使用指令**v-for**，给需要指定列表的**第一个li**中进行添加（表示要根据vm中的列表数据进行渲染），内容为："形参 in data中存储列表的数组"（of也行）  
	- 数据格式：data中使用数组存储，每个li中的数据用一个对象表示，通过此对象需要id属性和其他自定义属性  
	- 在Vue中渲染多个li列表数据，每一个li需要设定id表示属性，通过key来进行指定，在列表中使用**:key="形参.id"**进行绑定唯一表示（如果不写在Vue中并没有什么报错，但是最好还是需要写）(另外里面的值除了id还可以是其他的唯一值，比如index，只要保证值唯一即可)  
	- 实际上v-for指定的内容形参可以有两个，使用括号进行包裹(p index)，第一个为数组中的对象，第二个就是数组中对应的索引值  
* 当然，除了遍历数组，还能直接遍历对象、字符串（for in、for of），也能遍历指定次数（a in 5???）  
* 总结：  
> 用于展示列表数据  
> 语法：v-for="(item, index) in xxx" :key="yyy"  
> 可遍历：数组、对象、字符串、指定次数  

### key的作用与原理  
1. 虚拟DOM中key的作用：  
> key 是虚拟DOM对象的标识，当状态中的数据发生变化时，Vue会根据**新数据**生成**新的虚拟DOM**，随后Vue进行**新的虚拟DOM**与**旧的虚拟DOM**的差异比较，比较规则如下  

2. 对比规则：  
> 1. 旧虚拟DOM中找到了与新虚拟DOM中相同的key：  
> 	(1).若虚拟DOM中内容元素没变，则直接复用之前的真实DOM  
> 	(2).若虚拟DOM中的内容元素变了，则生成新的真实DOM，随后替换掉页面中之前的真实DOM  
> 2. 旧虚拟DOM中未找到与新虚拟DOM相同的key：  
> 	创建新的真实DOM，随后渲染到页面内  

3. 使用index作为key可能引发的问题：  
> 1. 若对数据进行逆序添加、删除一些等破坏顺序操作：  
> 	会产生没有必要的真实DOM更新->页面效果没有影响，但是效率低下  
> 2. 如果结构中还包含输入类的DOM：  
> 	会产生错误的DOM更新->界面存在问题  
> 注意：默认v-for指令如果不写key，默认以index作为key处理  

4. 开发中如何选择key？  
> 1. 最耗使用每条数据唯一的标识符作为key  
> 2. 如果不存在对数据的逆序添加、逆序删除等破坏顺序操作，仅仅用于渲染列表作为展示，使用index作为key是没有问题的  

### 列表过滤

### 列表排序  
* 只需要按钮设置修改vm中的data属性，在计算属性列表数组的时候，根据条件进行排序即可  
* 下面是例子：  
```html
<body>
    <div class="root">
        <input type="text" id="sousuo" v-model:value="search" placeholder="请输入名字"> <button v-on:click="sortType = 1">升序</button><button @click="sortType=2">降序</button><button @click="sortType=0">恢复</button>
        <ul>
            <li v-for="p of filtrArr" :key="p.id">
                {{p.name}} 时间跨度:{{p.time}}
            </li>
        </ul>
    </div>
    <script>
        new Vue({
            el:".root",
            data:{
                sortType: 0, // 0原来的排序，1升序 2降序
                search:"",
                arr:[
                    {id: "001", name: "-千恋万花", time: 2},
                    {id: "002", name: "-魔女的夜宴^", time: 1},
                    {id: "003", name: "RIDDLE JOKER^", time: 3}
                ],
            },
            computed:{
                filtrArr(){
                    const newArr =  this.arr.filter((e)=>{
                        return e.name.indexOf(this.search) !== -1;
                    });

                    if (this.sortType)
                    {
                        newArr.sort((p1, p2)=>{
                            return this.sortType === 1 ? p1.time-p2.time : p2.time-p1.time;
                        })
                    }

                    return newArr;
                }
            }
        });
    </script>
</body>
```

## 更新问题-Vue监视底层逻辑  
* 当我们修改Vue中Data数据中的一个数组中的对象时，如果直接数组[index] = {}这种方式去修改，实际上底层是修改了的，但是无论是页面呈现和Vue监视都没有监测到对应的对象发生了改变 -- 问题提出  
### Vue检测对象的变化  
* Vue如何检测data中对象发生了变化？  
	- 在代码中Vue:data->传入到实例vm->``_data``的过程中：  
		1. 加工data  
			* 设置了setter和getter - 完成了响应式？  
			* reactive，即能够实现对此对象的的set修改能够引起模板中的变化  
		2. ``vm._data = data``  
	- 我们可以简单模拟一下Vue检测data数据，并且能引发模板上变化的基本过程：  
> 使用到的核心函数仍然是Object.defineproperty  
> 我们需要明确目的，我们是通过Vue对象解析模板的，那么data中的数据一旦发生改变，那么Vue中应该知道，并且完成对应的操作。因为无法直接对data自身进行监视（自己监视自己会触发递归导致栈溢出），所以使用一个对象代替自身去监视，最后赋给Vue对象  
> 当然，下面演示只是对表面的第一层对象进行了封装，实际Vue中，是实现了递归操作，对对象中的对象，以及数组中的对象，均做了监视，这里不在演示  

```js
        // 下面的data模拟实际传入Vue配置项中的data对象，这里只是简单模拟，不对对象中的对象、数组中的对象进行考虑
        let data = {
            name:"柒海",
            hobby: "universe"
        };
        // 我们需要一个对象代理data进行监视，需要构造的时候对其进行监视，可以利用对象的构造函数  
        // 下面使用的是旧类的构造方法，别忘了函数也是一个对象，默认自己就是构造方法 
        function agencyObject(data){
            // data是一个对象，获取其全部的key，分别对其进行监视  
            let keysArr = Object.keys(data);
            // 遍历数组即可  
            for(let key of keysArr)
            {
                Object.defineProperty(this, key, {
                    get(){
                        return data[key];
                    },
                    set(val){
                        data[key] = val;
                        console.log("此时属性：" + key + "的值发生了变化，我需要将对应DOM树上的结构进行修改");
                    }
                });
            }
        }
        let obs = new agencyObject(data);
        let myVue = {};
        myVue._data = data = obs;
```

### Vue.set的使用  
* 如果没有在创建Vue实例的时候传入对应需要响应式的数据，那么之后直接加入也不会进行响应式  
* 可以借助Vue提供的方法set=>Vue.set(target, key, val) 或者vm.$set(target, key, val)  
	- vm.数据名/this.  
	- 给目标对象添加新的响应式数据  
* 此时添加到目标上的数据就和之前配置项的一样是响应式的了  
* 局限：不让你直接给data、vm本身添加一个响应式的对象！  
* 可以使用在想要创建一个响应式数据的情况（原本是没有的）  

### Vue检测数组中的变化  
* 对于数组内元素的改变是不会引起数组的变化的话，换句话说Vue检测不到  
	- 数组内的元素如果是对象，那么对象中的元素还是响应式的（被检测的）  
* 对于数组，如果对数组发生了结构性破坏的改变，则会引起数组的检测（push、pop、shift、unshift、splice（可以使用Vue.set同样实现部分功能）、sort、reverse）  
* 原理：数组中的这些方法被Vue包装了一遍（1.首先调用原始的push、2.重新解析模板，虚拟DOM）  
### 总结Vue数据监测  
1. Vue会监视Data中所有层次的数据  
2. 如何检测对象中的数据？  
	- 通过setter实现监视，要在new Vue时就传入要监测的数据  
	1. 对象后追加的数据，Vue默认不做响应式处理  
	2. 如果需要做响应式处理，使用setAPI  
3. 如何检测数组中的数据？  
	- 通过包裹数据更新元素的方法实现，本质做了两件事情：  
	1. 调用原生对应的方法对数组进行更新  
	2. 重新解析模板，进而更新界面  
4. 特别注意：Vue.set不能给Vue以及``Vue._data``添加响应式属性！

## 过滤器  
* 在模板上写正常展示的数据，如果想要处理，在模板上对该数据（插入语法）{{time | 过滤器名字}}  
* 在vue配置项中增加filters配置即可（过滤器的本质就是一个函数，所谓的过滤器名也就是函数名），在模板中的管道语法，前面的数据会作为参数传入这个函数里面，然后在函数里做出对应的操作即可，最后返回即可  
* 过滤器的第一个参数不会发生改变（始终就是 |前面的数据），后续的参数作为后面的参数写即可，在模板上需要书写清楚  
* 过滤可以一层一层的，最后的结果会在模板上进行渲染：  
	- ``数据1 | 过滤器1 | 过滤器2...``  
* 使用Vue.filter可以设置全局过滤器，参数为：1过滤器名字 2回调函数  
* 除了在插值语法上使用，指令语法中的v-bind也能使用（其余不能使用）  

## 内置指令  
* 之前学过的指令：  
	1. v-bind：单向绑定解析表达式，可以简写为:xxx  
	2. v-model: 双向数据绑定，对于v-model:value=xxx可以简写为v-model=xxx  
	3. v-for: 遍历数组/对象/字符串，一般用于列表中的第一个li上  
	4. v-on: 绑定事件监听，可简写为@  
	5. v-if: 条件渲染（动态的控制节点是否存在）  
	6. v-else/v-else-if: 条件渲染（动态控制节点是否存在）  
	7. v-show： 条件渲染（动态控制节点是否展示）  

* v-text指令，v-text="xxx"能够控制对应标签中的文本，并且里面不会当成标签进行解析（同js中操作textContendt那样）  
	- 与插值语法的不同：v-text会替换节点中的内容，插值语法不会  
* v-html指令类似v-text，唯一不同的就是支持解析文本中的标签（同js中的innerHtml那样）  
	- 严重注意！所有能够直接插入结构渲染成html的是非常危险的，因为容易遭到xss注入攻击，盗取用户的cookie信息等  
	- 不能相信用户输入（用户提交），只能在可信的东西上使用v-html  

* v-cloak指令，在标签上直接写入，配合css的属性选择器可以让Vue脚本没有加载好的情况下让其不在直接渲染到网页上，等待Vue加载好后，这些指令就会被消除  
	- 解决网速过慢的情况下，未经解析的Vue代码渲染到网页上去  

* v-once指令，在标签上直接写入（不存在值），v-once在所有节点初次进行动态渲染之后，就会被视为静态内容了，以后数据的改变不会引起v-once所在结构的更新，可以用于优化性能  
* v-pre指令, 在标签中直接写入（不存在值），可以让Vue跳过其所在节点的编译过程，可以用它来跳过：没有使用指令语法、插值语法的节点，可以加快编译  

## 自定义指令  
* 在Vue的配置项：**directives**，值为一个对象，在模型中定义v-自定义指令名，在配置项中直接自定义指令名: 后面的值可以为函数或者对象  
	1. 值为函数，函数会传递两个参数：element真正的指令绑定的dom结构、binding，绑定的指令对象，里面存在js表达式（自定义指令=后面的东西）、value表达式返回的值等等  
		- 函数调用的时机：1.指令与元素成功绑定的时候（一上来）2.指令所在的模板被重新解析的时候  
	2. 值为对象：针对于Vue针对指令对对应模板操作的时机调用不同的函数。  
		- bind(element,binding )指令和元素成功绑定时  
		- inserted(element,binding)指令所在元素被插入页面的时候  
		- update(element,binding)指令所在的元素被重新解析时  
	* 实际上第一个函数时将对象中的两个常用的函数绑定和更新时执行同样的函数  
* 注意：  
	1. 指令名命名的时候不可以使用驼峰命名法（大小写可能对不上配置项里的），官方推荐多个单词用-隔开，需要注意在配置项写名字的时候就需要使用引号打起了  
	2. 注意所有自定义指令里面的函数，this都是window  
	3. 注意在当前定义的容器里定义的自定义指令都是局部指令，和过滤器类似，使用全局的方法：Vue.directive('指令名', {配置项}/函数)  

## 生命周期  
* 当Vue将模板解析完毕并且将初始的真实DOM放入页面（挂载完毕）后，会调用一个函数，作为Vue的配置项，名字叫做mounted，并且是一个函数。this就是一个Vue对象  
* 上述就是Vue生命周期的一个阶段，也叫做Vue的生命周期钩子。所谓的生命周期函数就是Vue在一些关键时刻帮我们调用的一些特殊名称的函数  
* 生命周期图示：![生命周期图示](https://v2.cn.vuejs.org/images/lifecycle.png)  
### 挂载流程-template配置项  
1. init初始化：生命周期（生命周期函数定义）、事件（指定规则），**但是数据代理还未开始**（data:{n:1}并没有代理成为``_data``）  
* **beforeCreate**生命周期函数-创建之前，无法通过vm访问到data中的数据、methods中的方法  
2. init初始化：数据监测（监测对象、数组、匹配getter、setter、对数组方法进行二次包装）、数据代理  
* **created**生命周期函数-创建，可以通过vm访问到data中的数据以及methods中的方法  
3. Vue开始解析模板，生成虚拟DOM（内存中），页面还不能显示解析好的内容  
	- 是否设置el选项  
		* 如果没有设置，那么等待设置vm.$mount(el)在进行下面的步骤  
	- 是否设置template选项（template配置项就是一个字符串，里面设置对于容器内的网页DOM结构）   
		* 设置了：直接以其为模板进行解析（注意此设置只能存在一个根节点（外面用一层div包裹，并且一般使用模板字符串``））,并且替换el设置标签的容器（注意不能使用template作为根节点进行包裹）  
		* 没有设置以el标签（包括内部）作为模板进行渲染  
* **beforeMount**生命周期函数-挂载之前，页面呈现的是未经Vue编译的DOM结构，所有对DOM的操作，最终都不奏效（后面都会对其进行替换）  
4. 创建vm.$el替换掉整个el中的内容->将内存中的虚拟DOM转换为真实的DOM插入页面（vm.$el中存了一份真实DOM-便于复用）  
* **mounted**生命周期函数-挂载，页面中呈现的是经过Vue编译的DOM，对DOM的操作均有效（尽可能避免）。
	- 至此初始化过程结束，一般在此进行：开启定时器、发送网络请求、订阅消息、绑定自定义事件、等初始化操作  
### 更新流程  
5. Mounted  
	* 数据更新的时候  
	* **beforeUpdate**生命周期函数-更新之前，此时：数据是新的，但是页面是旧的  
	* 根据新数据生成新的虚拟DOM，和旧的虚拟DOM比较，最终完成页面更新：Model->Viewd的更新  
	* **updated**生命周期函数-更新之后，此时：数据和页面保持同步  
### 销毁流程  
* 当**vm.$destroy**函数被调用的时候，销毁vm（清理它与其他实例的连接-组件，解绑全部指令和事件监听器（指的是自定义事件））  
* **beforeDestory**生命周期函数-销毁之前，此时vm中的所有都可以使用（但是不会进行更新流程），但是马上要执行销毁过程，一般在此阶段：关闭定时器、取消订阅消息、解绑自定义事件等收尾操作  
6. vm的组件，监视，自定义事件全部移除（原生挂载的事件并不会被消除）  
* **destroyed**生命周期函数-销毁之后  
### 总结  
1. 数据监测数据代理之前和之后  
	- beforeCreate  
	- created  
2. 真实DOM挂载之前和之后  
	- beforeMount  
	- mounted - 重要的钩子：(一上来的时候：发送ajax请求、启动定时器、绑定自定义事件、订阅消息)  
3. 数据更新之前和之后  
	- beforeUpdate  
	- updated  
4. vm销毁之前和之后  
	- beforeDestory - 重要的钩子（最后的时候：清除定时器、解绑自定义事件、取消订阅消息等）  
	- destroyed

## 对组件化的理解  
* 传统方式编写应用：css、html、JavaScript混杂在一起  
	1. 依赖关系混乱，不好维护  
	2. 代码复用率不高（主要是html文件）  
* 组件方式编写应用：每一部分使用html、css、js片段（只是这些部分，封装到一个盒子里，与外界无关）  
* 组件的定义：实现应用中**局部**功能**代码**和**资源**的**集合**  
	- 作用：复用编码，简化项目编码，提高运行效率  
* 模块化：  
	- 当应用js都是以模块来编写的，此应用就是一个模块化的应用  
* 组件化：  
	- 当应用中的功能都是多组件的方式进行编写的，那么就是组件化应用  
## 组件的编写  
### 非单文件组件-components配置项  
* 一个文件中包含n个组件-a.html  
* Vue中创建组件的方式：**Vue.extend()**  
	- 传入参数为配置对象  
	- 注意配置对象几乎和Vue原本的配置对象一致  
	- 可以简写，直接从``const test = Vue.extend(options)``替换为``const test = options``  
* 不同点：  
	1. 组件不能书写el配置项，因为最终所有组件都会被一个Vue进行管理，由vm决定服务于哪个容器  
	2. data中配置不能以对象形式作为value，而是应该使用函数返回对象的形式（Vue两种都可以），这样是为了保证复用的时候得到的data对象都是全新的data对象，否则就会出现连带更新的问题  

* Vue中使用组件需要分为三步：  
	1. 创建组件  
	2. 注册组件（局部注册）  
		- 在Vue对象中使用全新的配置项：**components**，value为对象，里面配置组件的对象即可  
		- 可以以组件在vue中的名字（最终的组件名）：组件的名字，如果一致直接简写为组件的名字即可  
	3. 使用组件  
		- 首先组件需要存在意义：结构和数据（结构由配置项template实现）  
		- 编写组件标签，是一个双标签，里面写着最终的组件名即可（也可以写单标签，但是注意/结束符，并且需要在**脚手架环境下使用**，存在bug）  
* 注册组件可以使用全局注册：Vue.component('组件名', 组件对象)  

#### 组件的几个注意点-name配置项  
* 组件名写法：  
	- 推荐写法：单个单词：纯小写、首字母大写；多个单词：全部小写，之间使用-间隔、大驼峰（但是需要需要在脚手架的环境下书写-webpack搭建的工作流）  
	- 组件名需要避开html中的元素预留的元素名（大写小写均不可使用）  
	- 如果需要让Vue开发者工具显示出自己想要的组件名字，可以在组件配置中加上name配置项指定名字（当然首字母也还是大写）  
#### 组件的嵌套  
* 可以直接注册到父组件中的components项目配置中去，这样可以完成一个简单的组件嵌套  
	- 注册给谁的组件，就需要给父组件的结构template中写名子组件  
* 一般标准化开发中，我们需要定义一个组件app管理所有的组件，app由vm进行托管  

#### VueComponent  
* 可以通过log函数输出我们获取组件之后的对象，可以发现通过Vue.extend(option)获取的组件对象实际上是一个构造函数，名字就叫做VueComponent  
* 我们在对于存在组件的组件或者Vue的模板上，写```<test/>/<test></test>``，Vue解析的时候会帮我们创建test组件的实例对象，即Vue帮我们执行：new VueComponent(options)  
* 特别注意：每次调用Vue.extend,返回的都是一个全新的VueComponent  
* 关于this指向  
	1. 组件对象里面配置的普通函数，this为VueComponent实例对象  
	2. Vue对象里配置的普通函数，this为Vue实例对象  
* VueComponent的实例对象简称：vc  ，在vm/vc中可以看到属于它的组件对象：$children  

#### 一个重要的内置关系  
* ``VueComponent.prototype.__proto__ ==== Vue.prototype``  
* 所以组件对象实际上时继承自Vue对象的  
* Vue的原型链：Vue - Vue的原型-Object的原型对象 -null  
* VueComponent原型链：VueComponet-VueComponet的原型-Vue的原型-Object的原型对象-null

### render配置项  
* 在分析脚手架中的main.js文件中，应该出现的template和components配置项没有出现，实际上去运用这些反而会进行报错- 使用npm run serve去运行的话，解决方法：1.使用render2.使用带有模板解析器的vue（完整版的Vue）  
	* 实际上在脚手架上写的引入vue：``import Vue from 'vue'``引入的是dist/vue.runtime.esm.js（精简版的vue，不会进行解析模板）  -在对应目录下package.json下的module属性。最全的vue文件就是vue/dist/vue.js  
* 使用render配置项-是一个函数，vue帮其调用，存在返回值，参数是一个createElement，创建元素，是一个函数，用其进行创建元素渲染页面。并且返回其渲染的页面即可  
```js
new Vue({
    el:'#app',
    render(createElement){
        return createElement('h1', '你好啊');
    }
});
```

- 对于render函数，存在精简的方式：(App是一个组件，里面配置着具体的内容，不需要自己进行设置了，直接下面这种写就是创建脚手架的时候初始化的方式)  
```js
	render h=>h(App), 
```

* 为何这样设计？  
	- vue包括核心和模板解析器  
	- 模板解析器基本占据Vue总共的1/3,如果一直使用在开发的时候并没有什么问题，但是最后写完，通过webpack打包会生成最纯粹的文件：css、js、html。此时模板解析器就没有什么作用了  
	- 带有runtime的vue.js存在特点：将vue解析器的代码给干掉了  
	- 带有common-commonjs模块化

### ref标签属性-vue  
* 在Vue中可以对模型元素添加属性ref='name'，之后在vue的方法中可以通过this.$refs.name即可获取到  
* 可以类比记忆js通过id获取对应的DOM元素，即id的替代者-被用来给元素或子组件注册引用信息  
* 注意：  
	如果对组件进行标识，获取到的就是组件实例对象。但是如果使用的是传统js，获取的是其组件渲染出来的整个真实DOM  

### 使用组件传参-props配置项  
* 当使用一些组件的时候，我们想要设定对应组件中的一些数据的值  
	* 在使用组件的地方，通过类似于**属性名= "属性值"**的方式对对应组件在网页结构中（template）中进行传值即可(注意必须是引号，如果想传入非字符串的值，可以对属性前面增加v-bind，可以将引号里面的值变成js表达式进行传入)  
	* 在编写组件的vue文件中，对于一个vuecomponent实例中的配置项需要设置props配置项，对其进行设置使用即可  
* props配置项  
	1. 简单声明接收：值传递一个数组，里面写好对应的数据名（字符串），顺序不重要  
	2. 对象数据类型限制接收：对象里面全是key-value，value为js中的数据类型，对对应属性值进行类型限制（这样会在传入不匹配的值的时候，出现报错）  
	3. 对象配置项（类型、必要性、默认值）接收：对象里是key-value，key是对应当前组件的data数据，value是一个配置对象，里面存在这些配置：
		- type-数据类型  
		- required-必要性（bool如果设置了没有必要，那么此属性不传也行，注意此配置默认为不必要）  
		- default-默认值（不传对应数据的话，一般需要配置默认值，否则报错）  
* 注意：  
	- props不要瞎声明  
	- props外部传过来的属性不可修改（有效果，但是会进行报错-因为会让vue存在一些奇怪的问题）  
	- 注意声明外部传入的属性prop不能和内部data中定义的数据名字发送冲突（效果以外部为主）  
		* 利用此效果，我们可以实现一个简单修改外部传入属性但是不报错（实际并没有修改，只是将其作为值传递给了内部数据，我们是对内部数据进行的修改）myAge=this.age(age是props中声明的外部传入数据)  
	- 不能将Vue使用的属性名字作为你想要传递给组件的参数名  

### 混入-mixin配置项  
* 对于多个组件，可能存在**相同的配置项**，我们可以对对应的配置项（比如一些方法）进行混入，来提高代码的复用性  
* 首先准备配置项，在一个js文件中，写入对象里面即可（配置项）,注意需要进行暴露（可以分别、默认暴露.....）  
```js
export const myMixin = {
    methods:{
        test(){
            alert('你好');
        }
    }
}
```

* 其次在需要复用配置项的组件里面，import引入对应的组件配置对象（注意暴露引入的方式）  
* 在组件配置里面，使用配置项**mixins**，值为数组，数组中直接传入复用对象即可  
* 注意：
	1. 如果混合配置项的数据和当前组件配置中的数据发生冲突，那么以当前组件的数据为主  
	2. 如果生命周期钩子（生命周期函数）均有则不会发生覆盖或者报错，则是均执行，执行顺序以混入->当前  

* 上面为局部引入，其实也会出现复用的情况，可以使用全局混入，在main.js中进行设置即可,**Vue.maxin(混入配置对象)**  
```js
	import {myMixin} from './mixin.js'
	Vue.maxin(myMixin);
```
* 需要注意，这样的话当前vm、vc均会存在相同配置  

### Vue插件  
* 在src中定义plugins.js专门来编写引入插件的脚本  
* 在对应的一个对象中，定义方法**install**，注意别忘记暴露（如果只要一个对象可以不需要变量名进行接收）  
	- install的第一个参数接收，是vue的构造函数，其次都是Vue.use中传过来的其他参数  
	- 可以在此处对Vue的各种全局配置、原型对象等进行操作：过滤器、全局指令、混入...  
* 在main.js 即定义Vue的地方去应用插件：**import plugins from './plugins.js',并且使用方法Vue.use(plugins);**即可应用插件  

### scoped属性-阻止冲突样式  
* 组件中的样式编写最终是都会汇总到一起的。所以编写的时候容易出现类名冲突  
* 解决这样的问题，可以在组件的style标签上增加scoped属性，这里面的全部样式只是负责当前vue中的结构

### 安装id生成库-nanoid  
- npm i nanoid  
* 使用分别暴露引入即可：``import {nanoid} from 'nanoid'``  
* 使用：``nanoid();``  

### 案例部分代码  
* App.vue  
```vue
<template>
    <div id="app">
        <ToDoHead :addToDo="addToDo"></ToDoHead>
        <div v-show="toDos.length > 0">
            <ToDoList :toDos="toDos" :changeToDo="changeToDo" :removeToDo="removeToDo"></ToDoList>
            <ToDoFooter :toDos="toDos" :changeAllToDo="changeAllToDo" :deleteAllToDoFinish="deleteAllToDoFinish"></ToDoFooter>
        </div>
    </div>
</template>

<script>
    import {nanoid} from 'nanoid'
    import ToDoHead from './components/ToDoHead.vue'
    import ToDoList from './components/ToDoList.vue'
    import ToDoFooter from './components/ToDoFooter.vue'

    export default {
        name: 'App',
        components: {ToDoHead,ToDoList,ToDoFooter},
        data() {
            return {
                toDos: [
                    {id: '001', name: '学习vue', finish: true},
                    {id: '002', name: '学习redis', finish: false},
                    {id: '003', name: '复习数据结构和算法', finish: false}
                ]       
            }
        },
        methods: {
            // 改变当前id任务的状态
            changeToDo(id) {
                for (let toDo of this.toDos){
                    if (toDo.id === id){
                        toDo.finish = !toDo.finish;
                        break;
                    }
                }
            },
            // 删除当前id任务在列表中
            removeToDo(id) {
                for (let i = 0; i < this.toDos.length; ++i){
                    if (this.toDos[i].id === id){
                        this.toDos.splice(i, 1);
                        break;
                    }
                }
            },
            // 添加一个任务在列表最开始
            addToDo(name) {
                if (name === '') return;
                const newToDoObj = {id:nanoid(), name, finish: false};
                this.toDos.unshift(newToDoObj);
            },
            // 修改全体列表的状态
            changeAllToDo(allChange){
                this.toDos.forEach((toDo)=>toDo.finish=allChange);
            },
            // 删除所有选中事件
            deleteAllToDoFinish(){
                this.toDos = this.toDos.filter((toDo)=>!toDo.finish);
            }
        }
    }
</script>

<style>
    * {
        margin: 0;
        padding: 0;
    }
    ul {
        list-style: none;
    }

    #app {
        width: 500px;
        padding: 10px;
        margin: 50px auto;
        border: 1px solid black;
        background-color:darksalmon;
    }
</style>
```

### 案例优化4：增加编辑功能  
* 对每个todo对象增加一个属性标识当前是否处在编辑状态  
* 注意直接对对象内原本没有的属性进行操作不会引起响应式的变化，需要使用Vue.set或者this.$set即可  
* 注意bug：需要一上来自动获取焦点（focus，需要注意，需要Vue重新渲染到网页上时-真正的DOM，调用它才会存在效果），否则触发不了丢失焦点修改数据的函数，另外需要对修改的数据进行简单校验一下  
	- 解决自动获取焦点：可以设置一个定时器，解析完毕在获取焦点就存在效果。（注意定时器的队列-底层原理）除此之外，可以利用官方的api：**this.$nextTick(回调)**，此时会在下一次DOM节点更新完毕后调用（非常有用）  
```vue
// ToDoItem.vue
    export default {
        name: 'ToDoItem',
        props: ['toDoObj'],
        methods: {
            changeToDo(id){
                this.$bus.$emit('changeToDo', id);
            },
            removeToDo(id){
                this.$bus.$emit('removeToDo', id);
            },
            editToDO(todo){
                // 判断当前是否存在这个属性
                if (Object.hasOwn(this.toDoObj, 'edit')) todo.edit = true;
                else this.$set(todo, 'edit', true);

                // 需要设置自动获取焦点
                // 注意需要模型渲染完挂到网页上才起作用
                this.$nextTick(()=>{
                    this.$refs.edit.focus();  // 自动获取焦点
                });
            },
            editValue(todo, e){
                // 此时修改数据
                if (e.target.value === '') alert("编辑不可为空");
                else todo.name = e.target.value;
                todo.edit = false;
            }

        },
    }
```

## 组件间通信  
### 组件的自定义事件-父与子  
#### 绑定事件  
* 可以使用指令v-on绑定一些自定义事件给组件，并且由对应的组件触发此事件  
	- 除了直接在模型上给组件绑定事件，另外可以设置ref属性标识对应的模型，在父组件的挂载完毕生命周期钩子事件中获取对应的组件对其进行挂载即可：**this.$refs.test.$on('事件名', 回调函数对象)（$once可以实现只能触发一次）**  
	- 这种方式能够实现异步操作，比较灵活  
* 组件触发对应的事件通过：**vc.$emit('绑定的事件名', 传参)**, 此时就可以让事件触发，调用绑定时，后面的js表达式  
	- 对于传参，在绑定事件的时候，回调函数并不需要主动调用时候写接收（意思是比如v-on:test='Test',这个Test不需要显示写参数进行接收），参数直接可以传递给回调函数内部，需要在定义的时候进行接收即可。另外，通过接收一个参数，如果传递多个，一般可以将多余的利用可变参数...进行接收  
* 这样可以通过一个自定义事件，完成了子到父的一个传参过程（区别于之前的子调用父传过来的函数达到子给父传东西的效果，这次是子主动传参了，根据自己身上绑定事件）  
#### 解绑事件  
* 给哪个组件绑的自定义事件，就让哪个组件去自己解绑去  
* 解绑一个自定义事件：**vc.$off('绑定的事件名')**  
* 解绑多个自定义事件：**vc.$off(['事件1', '事件2'])**  
	- 解绑全部自定义事件：**vc.$off()**  
* 当然，如果当前组件被销毁了，自身的这些自定义事件也全部都不奏效了  

#### 注意事项：  
* 注意给自定义函数中的回调函数this：  
	1. this为当前父组件（即给子组件设置自定义组件的哪个组件），回调函数要么在当前组件配置项的methods中或者设置回调函数使用箭头函数  
	2. this为对应那个组件的，回调含本数需要设置传入箭头函数  
* 所有给组件增加的事件其实Vue都默认的会识别为自定义事件，如果不想通过组件自身vc.$emit去调用，在父组件中给子组件设置事件的时候加上**修饰符.native**即可：``< Test @click.native='test'/>``，相当于此时将click交给了Test组件内template模型中最外的一层标签上了  
* 一般利用自定义事件完成子与父组件之间的通信，因为在父组件上给子组件绑定事件，那么回调函数是留在父组件身上的，子组件就可以在合适的时机触发事件，传递参数完成通信  

### 全局事件总线  
* 全局事件总线：能够实现任意组件间的通信  
* 类似于父组件给子组件绑定自定义事件，子组件在触发事件的同时给回调函数位于父组件的地方传递参数。全局事件其实就是：A组件给一个公共的X绑定一个事件，回调函数在A上，B组件想要给A传递参数，那么在合适的时机触发X上A绑定的事件，此时可以达成任意组件之间的通信  
* 对于公共的x组件，它应该具备如下的特点：  
	1. 保证所有的组件均能直接找到  
		- 给Vue的原型对象上赋值对象即可**Vue.prototype**  
	2. 可以调用到$on和$off以及$emit(这些方法都在Vue的原型对象上)  
		- 对象是一个vc、vm即可-**Vue.extend()**，注意此函数返回的是一个构造函数，需要new一下哦  
		- 如果使用vm，即不需要额外new一个VueComponent，可以在vm的beforeCreate生命周期钩子上赋值给Vue的原型对象即可。此时Vue中并没有解析模板，甚至事件监视、代理什么的也没有开始  

* 标准写法：安装全局事件总线$bus  
```js
new Vue({
	el:'#app',
	render: h=> h(App),
	beforeCreate(){
		Vue.prototype.$bus = this;
	}
});
```

* 组件给bus绑定事件，一般在组件摧毁的时候，去给bus解绑自定义事件``beforeDestroy(){this.$bus.$off('事件名');}``  

### 消息订阅与发布  
* 也能实现任意两个组件之间通信  
1. 订阅消息：消息名（需要数据）  
2. 发布消息：消息内容（数据提供）  

* 注意此技术是由第三方库支持的，Vue本身不提供这样的技术：  
	- pubsub-js库  
	- 安装：``npm i pubsub-js``  

* 在需要用到的消息与订阅的地方，引入库：``import pubsub from 'pubsub-js'``  
* 订阅消息：  
	- ``pubsub.subscribe('消息名', 回调函数)``  
	- 回调函数的参数：1消息名 2数据  
	- 返回值是一个id，类似于定时器那种  
* 发布消息：  
	- ``pubsub.publish('消息名', 参数)``  
* 取消订阅：  
	-  ``pubsub.unsubscribe(id)``  
	-  注意id需要通过subscribe进行获取  

## 过渡与动画  
* 首先必须书写动画一些动画样式或者过渡样式，封装到class里面，现在想要Vue帮我们实现能够动态切换class的效果？  
* 作用：在插入、更新、移除DOM元素的时，在合适的时候给元素添加样式类名  
* 图示过程类名：  
	- Enter进入  
		1. Opacity: 0 -**v-enter** 进入的起点   
		2. Opacity: 1-**v-enter-to** 进入的终点  
		- 进入的过程：**v-enter-active**  
	- Leave退出  
		1. Opacity: 1-**v-leave** 离开的起点  
		2. Opacity: 0-**v-leave-to** 离开的终点  
		- 离开的过程：**v-leave-active**  
* 写法：  
	1. 准备好样式：  
		- 如果当前组件没有定义其他过渡/动画name，直接带上面的v即可，有将v修改为name即可。动画一般只是写在过程的类名里  
	2. 使用**``<transition>``**包裹要过渡或者动画的元素，有多个需要配置name属性，注意和样式类名的name一致，并且子元素上需要写上v-show控制其是否进行渲染（注意，如果是插入，更新，移除的元素直接也行，不需要v-show进行渲染哦）  
		- 如果存在多个元素需要过渡，使用``<transition-group>``,并且子元素需要配置key属性，需要不一样  
		- 如果想要一开始网页加载就进入动画进入过程，那么加上属性appear即可

	* 准备好一个第三方动画库：比如Animate.css

		2. 不在style中书写类名，在transition标签上指定对应元素需要变化的类名：  
			- enter-active-class 进入存在的类名

## Vue-cli上配置代理服务器  
* 注意：  
	- 注意跨域问题：即网页上发送请求资源，需要遵循同源策略：即：**协议名、主机名、端口号需要一致**  
		- 浏览器会得到数据，但是不会呈现给前端  
		- 解决跨域问题：  
			1. cors：后端服务器，返回数据的时候携带一些特殊的响应头（真正解决跨域）  
			2. jsonp script src - 前端后端一起解决，并且解决get问题（post请求解决不了）  
			3. 代理服务器（常见）  
				- nginx 使用充当反向代理服务器  
				- vue-cli  

* 如果前端应用和后端API服务器没有运行在同一个主机上，需要在开发环境下将API请求代理到API服务器，这个问题可以使用vue.config.js中的devServer.proxy选项进行配置  
### 方式1-简单代理  
```vue
module.exports= {
    //...
    devServer: {
        proxy: '请求目标URL' // 注意只能写到端口号 相当于代理访问，从而避免跨域问题，返回给前端中的request接受数据
    }
}
```

* 需要注意，此时前端索要数据的url，前面的主机名端口号需要和代理服务器一致，一般为``http://localhost:8080``  
* 注意：  
	- 通过代理服务器访问数据，如果本地public文件夹存在同名文件，会优先访问同名文件，不会去请求服务器了  
	- 并且这样配置不能配置多个代理  
	- 并且不能灵活的控制是否使用代理  

### 方式2-灵活代理  
* 这个方式能够控制对应URL是否走代理服务、以及能够配置多个代理  
```js
module.exports = {
  devServer: {
    proxy: {
      '/api': { // 请求前缀（在端口号后面）：如果前端js中，URL带有前缀/api，就能走到这里面的代理，否则不会走代理 这里的api可以自己命名，并且通过不同的命名可以达成配置不同的代理服务器
        target: '<url>',  // 转发给谁，协议名 主机名 端口号
        pathRewrite: {'正则': '替换字符串'},  // 这里是重写路径，因为此时加上了/api的前缀了，这里的正则应该是^/api 然后字符串就应该是一个空字符串，这样代理服务器转发给服务器的时候路径才是去掉访问代理服务器前缀的正确URL
        ws: true,  // 用于支持websocket通信 
        changeOrigin: true // 此时代理服务器访问服务器时，会声称和服务器一样的URL - http协议中请求头中的host值
      },
      '/foo': {
        target: '<other_url>'
      }
    }
  }
}
```

* 场景：如果相同的组件，需要展示不同的css，如果直接修改组件，那么会用到很多v-show条件渲染，并且冗余不灵活，此时就用到插槽了  
### 默认插槽  
* 在原本的组件标签内（注意需要切换为双标签），在子内插入你想要的标签结构  
* 然后在组件标签内，使用标签``<slot></slot>``标识插入的标签结构所放置的位置  
* 需要注意：使用插槽，是在使用组件的文件中完成模型解析后，才插入到组件内的插槽里去的  
```vue
// 使用Test组件的vue
	<Test>
		<img>
	</Test>

// Test.vue
	<slot><slot>
```

### 具名插槽  
* 具有名字的插槽  
* 如果一个组件存在多个插槽，那么就需要指定名字了  
* 对slot标签使用name属性，指定名字即可，在外层模型中使用插槽的时候，使用属性**slot="name"**指定往哪个插槽里放即可  
	- 指明相同的name起的效果是追加的效果  
	- 对于template标签，可以直接：``v-solt:name``即可指明  

### 作用域插槽  
* 现在存在一个使用场景：组件内的数据不发生变化，但是结构样式存在变化  
* 还是使用默认插槽的场景，但是此时数据是在组件内的，在外面正常是无法使用到的  
* 在组件内的slot标签增加属性名和js表达式（使用绑定语法），可以传参，传给插槽的使用者``<slot :test="test"></slot>``  
* 在外面使用组件，向内部插结构的地方即可使用这些参数  
	- 外层必须使用template标签包裹，使用属性scope="参数"（或者使用slot-scope），此时从slot传递的参数就能通过此处参数进行接受（完成一个反向通信的过程）  
	- 注意接受的参数只有一个，是一个对象，其中在组件内部slot上传入的参数，通过对象.参数名即可获取  

* 注意作用域插槽同样也能设置为具名插槽  

# Vuex  
* 概念：专门在Vue中实现**集中式状态(状态也就是数据)**管理的一个Vue插件，对vue应用中多个组件的共享状态进行集中式的管理（读/写），也是一种组件间通信的方式，且适合于任意组件间通信  

* 注意是**共享数据**（全局事件总线也能实现），即对于某个组件中的数据，我们想要所有组件能够对其进行读取以及修改，但是实现比较复杂，定义的自定义事件也比较多  
* 那么我们可以将这些所谓的共享数据写在vuex中，每个组件都能对其中的数据进行读写  

* 什么适合使用vuex：  
	1. 多个组件依赖于同一个状态  
	2. 来自不同的组件行为需要变更同一状态  
	3. 业务逻辑非常复杂  


## Vuex的工作原理  
* Vuex  ：**Actions 动作行为（也是Object对象，并且存在Backend API后端接口） -Commit-> Mutations 加工维护 -Mutate（De）->State 数据（Object对象）**  
  - 对于Actions，存在一个场景，就是前端知道怎么操作，但是操作的适合对应的参数未知，可以通过后端接口（比如ajax）进行获取。（如果知道操作数，可以在组件里直接调用commit绕过Action操作），注意如果存在逻辑判断，还是需要Actions的  
  - 类比记忆：Actions类似服务员、Mutate类似于后厨、State类似于菜，而组件类似于客人  
  - 注意Vuex中的三个对象是由store进行管理（理由就是过渡的适合调用的方法就是store提供的）  

* **从State-Render->Vue components组件 - Dispatch->Action（形成闭环）**  
  - 在组件中操作Vuex中State的数据，通过dispatch指定要的动作和参数  
  - 在传入的回调函数（Actions）中调用commit，将其提交上去  
  - 提交后对应的调用会在Mutations中执行，其中会拿到对应操作的state数据以及操作参数，加工后得到State中的数据，然后vuex发现修改·1，重新渲染使用到State中的数据的模型  

## 搭建Vuex的开发环境  
* 安装vuex：``npm i vuex``  
	- 注意默认使用此安装的是vuex4版本（结合的是vue3，vue2中只能使用3版本）  
	- vue2中使用的话，需要指定安装版本：``npm i vuex@3``  

* 引入Vuex：``import Vuex from 'vuex'``  
* 使用插件：``Vue.use(Vuex)``  

  - 使用此插件后，创建vue的时候可以传入一个store配置项，此时vm和vc都能通过$store进行访问  
* 配置store  
	1. 可以在在src文件夹下创建文件夹vuex，并且内部定义一个store.js进行配置基础的东西  
	2. 在src下创建store文件夹，里面定义index.js进行配置（官方推荐）  
	- 该文件用户创建Vuex最为核心的store（中间的三个对象）  
	- 配置完毕后文件在main.js中引入``import store from './store'``，将store对象传递给Vue中的store配置项即可。**注意：需要先Vue.use(Vuex)需要先于store对象的创造。但是由于import始终是优先于当前文件的js的执行优先级的，那么将use在index.js文件中先机进行使用即可，别忘了先引入**  
```js
// 引入Vue，为了让插件先应用Vuex
import Vue from 'vue'

import Vuex from 'vuex'

// 先使用插件，优先级必须如此
Vue.use(Vuex);

// 准备actions-用于响应组件中的动作  
const actions = {}
// 准备mutations-用于操作数据（state）
const mutations = {}
// 准备state-用于存储数据
const state = {}

// 创建并且暴露store
export default new Vuex.Store({
    actions,
    mutations,
    state
});

```

* 到此Vuex的开发环境配置完毕  

## Vuex的使用  
* state中配置存储的数据  
* 向actions推送动作：**``this.$store.dispatch('actionType', 参数)``**  
* actionType就是配置actions的配置项，名字对应，值为一个函数  
	- 参数为：context(上下文，此时需要调用一个commit，可以理解为mini版本的store，也存在state)、value（传递过来的值）  
	- **``context.commit('mutationType', 参数)``**  
	- 业务逻辑都写在那里  
	- context：会给dispatc、commie、state。方便进行复杂的业务逻辑处理  
	- 注意如果在这里对数据进行操作，那么开发者工具是捕获不到的  
* mutationType同理就是mutations中的配置，名字对应，值为一个函数  
	- 编码规范：一般同类型操作在mutations里是全大写，在actions里就是小写  
	- 参数：state（处理后的state，经过了监视处理）、value（传递过来的参数）  
	- 这里编码的时候不要存在任何逻辑处理了，直接对数据操作  
* 读取state中的数据  
	- **``$store.state.数据名称``**  

### Vuex开发者工具  
* 里面会记录Mutations的动作  
* 上方记录的每一项中，最后一个秒表类似时间线，可以跳转到网页对应渲染的那一刻  点击不要了可以将其回退（必须严格安装顺序， 如果在中间点击取消，后面所有依赖其的内容都会消失）  第一个有点类似下载按钮的是合并的意思，会在同一个类型操作（一般对最后一个）合并到base state中  
## getters配置项  
* store存在一个配置项：getters（和actions、mutations、state同级）  
* 如果存在vuex中数据需要逻辑复杂进行处理，并且需要组件间进行复用，则推荐使用此配置项  
* 定义：  
```js
const state = {
    sum: 0
}
// 用于将state中数据进行加工
const getters = {
    bigSum(state){
        return state.sum*10;
    }
}
export default new Vuex.Store({
    actions,
    mutations,
    state,
    getters
})
```

* 使用： **$store.getters.状态名**  
* 类似于data和computed之间的关系  

## 优化vuex书写  
### mapState与mapGetters  
* 首先想要使用其优化掉$store.state/$store.getters.这些东西，需要先引入：  
	- ``import {mapState} from 'vuex'``  
	- ``import {mapGetters} from 'vuex'``  

* 参数：为一个对象，配置在当前组件的对应属性名和store中对应的状态名，都应该是字符串  
* 返回的也是一个对象，并且里面的属性也是key-value的形式，可以使用...在比如计算属性里面展开即可简化书写  
```js
computed:{
    ...mapState({test:'test'});  // 对象写法  
    ...mapState(['sum', 'school', 'test'])；  //数组写法：必须要当前计算属性名和vuex中state数据的名字一致 
}
```

* mapGetters类似  

### mapActions与mapMutations  
* 同样的，对于$store.commit和$store.dispatch调用也有简单调用方法优化  
	- ``import {mapActions, mapMutations} from 'vuex'``  
```js
	methods: {
		// 对象写法
        ...mapMutations({test:'TEST'}),
		// 数组写法
        ...mapMutations(['TEST'])  // 注意此时生成的函数名就需要和配置在vuex中mutations中的一致了
	}
	
```

* 注意，对于于之前自己写的test，比如如下的区分：  
```js
	test(){
        this.$store.commit('TEST', 2);
	}
// 实际mapMutations生成的commit  
	test(value){
		this.$store.commit('TEST', value);
	}
```

* 所以此时在调用的地方就需要传递参数，比如模板上直接传参即可  
* mapActions类似，只不过注意是dispatch方法  

## vuex模块化  
* 因为存在多种不同的功能，如果不同的功能全部挤在一个和vuex的某个对象中日后会变得难以维护  
* 为了避免这种问题，可以一开始分功能进行配置vuex，每个功能都配置上actions、mutations、state即可,为了后面能够模块化批量取出数据，**需要增加新的配置项：namespaced指定map取出的依据为当前的配置项名字**  
```js
const test1 = {
	namespace: true,
    actions: {
        a: function(),
        b: function(),
        test: function()
    },
    mutations: {},
    state: {
        abc: 1
    },
    getters: {
        testAbc(state){
            return state.abc;
        }
    }
};
const test2 = {
	namespace: true,
    actions: {
        c: 3
    },
    mutations: {},
    state: {},
    getters: {}
};

// 使用配置  
export default new Vuex.Store({
    modules:{
        test1,  // 注意这里是简写形式
        test2
    }
})
```

* 注意此时state就被分别保存在$store.state中的test1、test2对象中了，需要间接去调用  
	- 此时对于mapState，就需要模块化的批量取出数据了,并且每次只能取出一次模块的东西  
	* ``...mapState('test1', ['a', 'b'])``  
	* ``...mapState('test2', ['c'])``  
	- 同理，mapActions、mapMutations、mapGetters均类似  

* 对于没有配置map函数去获取模块化的getters、actions以及mutations，需要如下调用才能继续：  
	- ``this.$store.getters['getters/testAbc']``  
	- ``this.$store.commit('test1/Test', 参数)``  提交给mutations  
	- ``this.$store.dispatch('test1/test', 参数)``  提交给actions  


# Vue路由  
## 路由理解  
* 路由的概念：  
	1. 路由就是一组key-value的对应关系  
	2. 多个路由，需要经过路由器的管理  

* 在单页面应用中实现多种页面的跳转，借助VueRouter通过key（路径）->组件的一个过程  
* vue-router是vue的一个插件库，专门用来实现SPA应用  
* SPA应用：  
	1. 单页web应用  
	2. 整个应用只有一个完整的页面  
	3. 点击页面的导航链接不会刷新页面，只会做页面的局部更新  
	4. 数据需要通过ajax请求获取  
* 路由的理解：  
	1. 前端路由：  
		- value是component，用于展示页面的内容  
		- 工作过程：当浏览器的路径发送变化时，对应的组件就会显示  
	2. 后端路由：  
		- value是function，用于处理客户端提交的请求  
		- 工作过程：服务器接收到一个请求时，根据请求路径找到匹配的函数来处理请求，返回响应数据  

## 基本路由  
* 安装vue-router库：``npm install vue-router@3``  
	- 注意，vue-router3才能应用于vue2，vue-router4应用于vue3  
	- 并且是插件库  

* 使用  
	- 和上面的vuex类似，需要在src目录下创建router/index.js 去定义暴露router对象  
	- 在main.js使用组件使用后，在Vue对象中配置router即可  

* 创建整个应用的路由器  
```js
import VueRouter from 'vue-router'

// 引入组件
import About from 'path'
...

// 创建一个路由器
const router = new VueRouter({
	routes:[
        {
        	// 如果路由是/about，那么就展示About组件
            path: '/about',
            componet: About,
            meta: {自定义属性:值}  // meta自定义元信息
        },
        ......
        // 重定向，指定web在默认情况下展示的路由  
        {
            path: '*', // 这里/也行
            redirect: '/home';  // 首页路径
        }
	]
});
export default router;  // 暴露路由器
```

* 配置完后，导航栏上出现了``/#/``说明路由器已经开始工作了  

* 模型中使用vue-router提供的特殊标签：**``<router-link>``**控制路由跳转  
	- ``<router-link to="/about">切换路由</router-link>``  
	- 实际上此标签会最后渲染到模型上会变成a标签  
* 属性：  
	- 属性中使用**to**指定路由  
	- active-class指定哪个路由被激活，给它指定生效对应的class   
* 模型中使用vue-router提供的特殊标签：**``<router-view></router-view>``**会指定当前路由对应的组件呈现的位置  

* 注意点：  
	- 组件区分，因为一般组件是存在当前组件下component选项引入，并且模型上会用组件名标签的，而路由组件是通过路由器通过路由指定对应的组件渲染的，开发中一般对这些会存在一定的区分：pages文件夹一般存放路由组件，而原本的components文件夹存放一般组件即可   
	- 注意，如果没有使用的路由组件，切换的时候是被摧毁的  
	- 路由组件中的vc多了几个属性：$route(当前路由规则-路由信息)、$router(整个应用的路由器-编程式导航、路由跳转)  

### router-link中的replace属性  
* 对于路由，浏览器是以push压栈的方法存储每次路由历史记录的。如果不想暴露历史记录，那么每次路由更新的时候，不在push，而是replace（替换掉**当前记录**）即可  
* router-link默认开启的就是push默认，增加属性**replace**即可  

## 嵌套(多级)路由  
* 对于一开始在routes配置的规则是一级规则，在一级规则里面写的规则则是二级规则，依次类推  
* 给对应的一级规则（需要嵌套的路由）内部写即可发送多级路由，使用配置项**children**,值同样是数组  
```js
export default new VueRouter({
	routers: [
        {
            path: '/home',  // 一级路由
            component:Home,
            children: [
                {
                    path: 'news',  // 二级路由  
                    component: News
                }
                ,...
            ]
        }
        ,...
	]
});
```

* 直接在一级路由所在那个组件里面增加嵌套路由即可，并且注意，to属性里面路由必须写全  

* 注意：  
	- 嵌套路由写路由路径的时候不需要加`/`了  

## 路由传参  
* 有时候路由跳转展示的结构是一致的，只是数据不同。此时不能针对其书写路由组件了，而是集中复用到一个组件上，因为是结构相同数据不同，所以这里就会涉及到路由传参的问题  
* 路由接收的参数：  
1. query参数：
	- 字符串写法 ``/test?id=666&title=你好啊``  
	- 对象写法：(在router-link标签内取东西)   
	- 使用路由组件对象中的对象：**$route**中的query对象可以取出query传参  
```js
	// 对象写法
	to= "{
        path: '/test',// 组件路由
        query: {
            id: 111,
            title: '你好'
        }
	}"
```

2. params参数：  
	- 字符串写法：``/test/666/你好啊``  
	- 注意此时需要在对应路由配置里面，给path增加：``path: '/test/:id/:title'`` 对其进行占位然后方可接收参数  
	- 使用路由组件对象中的对象：**$route**中的params对象可以取出传参  
	- 对象写法类似上面，query改为params即可。并且注意，**此时此处不能指定path，只能通过name去指定路由，否则报错**  
	- 注意，如果占位了但是并没有传递参数（或者空串），网页上路径会出现问题。 
		- 对于没有传递参数：**指定parmas参数可传可不传**即:``/test/:id?``加上**?**即可   
		- 使用undefined解决params参数可以传递、不传递（空的字符串）-即在对面传参的时候带上``keyword: '' || undefined``  




## 命名路由  
* 在routes配置对象里面，存在一个配置项：name，即可给路由起名：  
```js
routes: [
    {
        name: 'ceshi',
        path: '/test',
        component: Test
    },...
]
```

* 名字可以简化编码模型里面to指定path的路由，即可以直接指定名字即可  
	- ``:to="{name:'test'}"``  


## props配置  
* 对于想简化路由组件接收参数，需要配置props配置（注意是路由的配置props，不是组件的）  
```js
export default new VueRouter({
    routes: [
        {
            name: 'ceshi'，
            path: '/test',
            component: Test,
            // 第一种写法，值为对象,该对象中的所有key-value会以props的形式传给当前的路由组件
            // props: {a:1, b:'hello'}
            // 第二种写法，值为布尔值，若布尔值为帧，会把该路由组件收到的所有params参数，以props的形式传给当前路由组件
            // props: true
            // 第三种写法,值为函数,返回的对象种每一组keyvalue都会传递给props-当前路由组件
            props($route){
                return  {key: value, ...};
                // value就可以写成：$route.query.id...
                // 另外，接收参数route是可以结构赋值的，比如{query:{id, title}}解构连续赋值
            }
        }
    ]
});
```

## 编程式路由导航  
* 有的时候，我们路由跳转最后并不想渲染成a标签。比如一些按钮什么的，或者一些特殊的业务需求。也就是说不能光使用router-link标签  
* 使用路由的全局唯一对象：**$router**-路由器对象，调用里面的push、和replace方法即可模拟router-link的效果  
	- 使用：类似与标签router-link中to的对象内容写法：  ``this.$router.push({name:'test', query:{id:m.id, title:m.titile}})`` 注意m可以由外面的函数传参进来  

* 同时，路由器对象上存在back和forward方法可以实现浏览器前进和后退路由的效果，还存在一个api go，参数为步数，正数为前进，负数为后退几步  
* 注意：  
	- 对于使用编程式路由跳转，如果多次相同情况下的跳转，会出现红色的警告（但是对程序没有影响），实际上比如push时候会返回一个Promise异常。解决问题可以除了传日对象外，还可以传入一个成功回调、失败的回调。即可解决此问题。失败的时候会捕获此错误（治标不治本）。此异常实际就是多次无意义的跳转。
	- push是VueRouter类的一个实例，是VueRouter原型对象上的方法。所以push的上下文就是VueRouter类的一个实例。解决多次跳转报异常，重写push|replace方法即可（在router/index.js下）。重写的时候，将成功回调、失败回调自动填进去。这样可以解决这个问题  
		* 使用call调用函数，保证上下文与实际调用的位置一致  
- 重写push|replace，让其多次跳转不报异常解决方案：  
```js
// router/index.js
let originPush = VueRouter.prototye.push;
VueRouter.prototype.push = function(location, resolve, reject){
	if (resolve && reject){
        originPush.call(this, location, resolve, reject);
	}
	else originPush.call(this, location, ()=>{}, ()=>{});
}
```

## 缓存路由组件  
* 因为切换路由的时候，会将原本的路由组件摧毁，之后切换回来重新生成，所以以前保存的input数据自然就会被清空，但是有的时候我们需要将这些数据进行缓存下来  

* 使用标签**keep-alive**双标签-保持活跃，即其路由组件不会进行销毁。属性需要进行指定：include=""指定目标组件缓存。如果不指定，那么在里面渲染的路由组件都会进行缓存(配置的话，其他路由组件不会进行一个渲染)  
	- 如果是多个组件：``:include="['test1', 'test2'...]"``即可  
```vue
	<keep-alive include="组件对象名">
		<router-view></router-view>
	</keep-alive>
```

## 两个新的生命周期钩子  
* 存在这样的一个需求：对于缓存组件内有些比如定时器，我们在它切换的时候并不想让它工作，但是同时想要保留缓存数据的这么一个需求  
* 前排提醒：路由组件**独有**的生命周期钩子  

* 无论其是否被摧毁，只要当前路由是当前组件，那么激活状态钩子被调用，否则就是未激活  
	- activated激活的  
	- deactivated未激活的  

## 路由守卫  
* 保护路由的权限：就是在一些数据（比如浏览器持久化数据、vuex中的数据等）特定的条件下才能展示的一些路由组件。（很简单的一个例子：管理员登录和普通用于登录，管理员能看到一些特殊的页面-可以用作这样的路由）  

### 全局路由守卫  
#### 全局前置  
* 使用router身上的特殊api：**beforeEach**，参数为指定的一个回调。
* 对于全局（只要存在路由器中形成一次跳转）来说，需要暴露路由器前进行设置，所以格式如下：  
	- 初始化的时候、切换之前调用回调函数  
	- 接收的参数是：to、from、next（去哪里、来自哪里、next放行函数）  
		* to、from都是精简的一个路由配置对象（$route），存在name、path等之前在route配置路由的配置项  

```js
	const router = new VueRouter({
        routes:[
            {}
        ]
	});
	
	// 全局前置路由守卫  
	router.beforeEach((to, from, next)=>{
        if (to.path ==='/home/test' && '逻辑判断') next();// 放行函数
	});
	
	export default router;  // 暴露
```

* 路由配置对象中存在meta配置，可以随意配置自己想设置的keyvalue（值为对象），可以配置，在路由守卫的时候，查看其是否放行  

#### 全局后置  
* 使用api **afterEach**，里面回调函数的参数同样是to、from（没有next）  
	- 在初始化、切换后进行调用  
* 使用场景：点击对应的路由组件，页签的标题切换名字（路由组件的标题可以存储在路由配置对象中的meta内）  
```js
router.afterEach((to, from)=>{
    document.title = to.meta.title || 'test';
}));
```

### 独享路由守卫  
* 类似于亲卫兵，此时只是在当前路由下进行守卫  
* 配置名字为beforeEnter（进入之前），配置在对应的路由配置对象中  
	- 进入之前里面同样是回调函数，参数为to、from、next  

### 组件内路由守卫  
* 在vc的配置项中,配置了路由器存在这些配置项：**beforeRouteEnter**、**beforeRouteLeave**  
	- 路由规则：进入该组件时被调用、离开该组件时被调用  
	- 参数都是：to、from、next  
* 注意都需要放行，才能进行切换路由组件  

### 路由器的工作模式  
* 在之前的路由配置中，可以发现一直存在这样的东西：``/#/``，实际上这是**哈希值**，发送请求的时候**不会作为路径的一部分（包括其极其后面的路径）发送给服务器**  
* 路由器的工作模式：  
	1. 默认hash工作模式，即开启了hash值  
	2. history工作模式-历史记录模式  
		- 此时没有hash值  
		- 兼容性略差（在后端部署成功后正常思路点没有问题，但是一旦在一些路由上重新刷新，那么此时会以次路由对服务器进行发送网络请求-没有返回404哦）  

* 如何解决后端部署history模式出现的404问题  
	- 需要使用中间件解决这些问题：（自己写有些麻烦）  
	- 也可以使用nginx解决  
	- nodejs中：connect-history-api-fallback  

* 在路由配置里面增加属性（VueRouter中） -**mode**  
	- 'hash'(默认)、'history'
